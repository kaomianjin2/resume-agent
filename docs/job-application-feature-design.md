# 求职投递功能设计

## 结论

第一版新增独立“求职投递”模块，覆盖 BOSS 直聘、拉勾、猎聘。系统根据已导入简历生成求职画像，使用用户现有 Chrome 登录态采集岗位，完成全条件筛选、岗位评估、改进建议和投递话术生成，最后由用户批量确认后执行投递。

## 范围

### 第一版包含

- 多平台岗位采集：BOSS 直聘、拉勾、猎聘。
- 简历驱动求职画像：复用现有 `resume_profile`。
- 全条件筛选：城市、远程、薪资、职级、经验、学历、行业、公司规模、融资阶段、技术栈、福利、发布时间、黑名单、白名单。
- 岗位评估：匹配分、硬条件状态、优势、风险、信息缺失项。
- 改进建议：简历补强建议和平台投递话术。
- 批量确认投递：用户勾选岗位并确认后再提交。
- 投递记录：保存投递状态、失败原因、平台提示和批次信息。
- 本地清理：提供清空求职数据入口。

### 第一版不包含

- 不自动改写或替换本地简历文件。
- 不保存平台账号、密码、cookie、token。
- 不把浏览器会话、账号凭据、联系方式等敏感信息传给 LLM。
- 不执行未确认的静默自动投递。
- 不修改 `/Users/cynicism/Desktop/面试` 原始资料。
- 不由 implementer 在任务分支内直接更新 `docs/architecture.md` 或 `docs/architecture.svg`；架构文档同步由主 agent 在任务合并后完成。

## 架构设计

### 求职画像层

- 输入：现有 `resume_parse` 输出的 `resume_profile`。
- 输出：岗位方向、技能栈、年限、项目关键词、默认搜索词、硬过滤条件、排序偏好。
- 用户可在 GUI 中补充或覆盖：城市、远程、薪资、职级、经验、学历、行业、公司规模、融资阶段、技术栈、福利、发布时间、黑名单、白名单。

### 平台适配器层

- BOSS 直聘、拉勾、猎聘各自实现一个适配器。
- 适配器职责：
  - 打开平台页面。
  - 使用用户现有 Chrome 登录态。
  - 按筛选条件搜索岗位。
  - 翻页并采集岗位列表。
  - 进入岗位详情页读取完整 JD。
  - 识别已投递、不可投递、登录失效、页面结构异常。
  - 在用户确认后执行投递动作。
- 适配器不做匹配判断，只输出标准化岗位对象和平台执行结果。

### Chrome 会话隔离层

- Chrome 登录态只存在于用户现有浏览器进程内。
- 平台适配器只能通过浏览器控制能力使用页面，不得读取、序列化、打印或保存 cookie、token、session id。
- 日志、SQLite、session state、node_runs、LLM prompt 必须统一走敏感字段脱敏检查。
- 会话隔离能力必须在平台适配器开发前完成，作为后续平台任务的前置依赖。

### 采集编排与进度层

- 多平台采集由统一编排器调度。
- 编排器记录平台级状态、分页进度、详情采集进度、失败原因、重试次数和人工接管状态。
- GUI 的采集进度页只读取编排器输出，不直接推断平台适配器内部状态。
- 编排器必须支持单个平台失败后继续保留其他平台结果。

### 评估与建议层

- 对标准化岗位批量执行 JD 解析、简历匹配、风险识别、改进建议和投递话术生成。
- 复用现有 `jd_parse`、`jd_match`、`resume_optimize` 的结构化节点思路。
- 输出岗位评估报告，用于 GUI 排序、筛选、详情展示和批量确认投递。

### 批量审核投递层

- GUI 展示候选岗位清单。
- 用户按平台、匹配分、硬条件状态、城市、薪资、公司、风险筛选岗位。
- 用户勾选目标岗位后进入确认弹窗。
- 确认弹窗展示岗位数量、平台分布、简历摘要、投递话术和风险提示。
- 用户确认后，系统按批次逐个调用平台适配器执行投递。
- 系统保存成功、失败、跳过、重复投递拦截等结果。

## 数据模型

### 标准岗位对象

标准岗位对象必须包含以下字段：

- `platform`：平台名称。
- `platform_job_id`：平台岗位 ID。
- `title`：岗位标题。
- `company_name`：公司名称。
- `location`：城市或办公地点。
- `remote_policy`：远程状态。
- `salary_range`：薪资范围。
- `level`：职级。
- `experience_requirement`：经验要求。
- `education_requirement`：学历要求。
- `industry`：行业。
- `company_size`：公司规模。
- `funding_stage`：融资阶段。
- `tech_stack`：技术栈。
- `benefits`：福利。
- `published_at`：发布时间。
- `detail_url`：岗位详情链接。
- `jd_text`：原始 JD 文本。
- `collected_at`：采集时间。
- `field_confidence`：字段置信度或缺失标记。

字段缺失时必须记录缺失状态，不得直接当作不符合条件。

### 筛选条件对象

筛选条件分为两类：

- `hard_filters`：用于明确排除岗位。
- `ranking_preferences`：用于排序和推荐，不直接排除岗位。

硬过滤覆盖城市、薪资下限、远程偏好、经验上下限、学历、黑名单公司、已投递岗位。排序偏好覆盖技术栈匹配、行业偏好、公司阶段、福利、发布时间、岗位成长性。

### 评估报告对象

评估报告必须包含：

- `score`：总分。
- `hard_filter_status`：硬条件状态。
- `strengths`：匹配优势。
- `risks`：缺口风险。
- `missing_information`：岗位信息缺失项。
- `resume_improvement_advice`：简历补强建议。
- `application_message`：投递话术。
- `recommended`：是否推荐投递。
- `recommendation_reason`：推荐理由。

### 投递记录对象

投递记录必须包含：

- `job_ref`：岗位引用。
- `platform`：平台。
- `confirmation_batch_id`：确认批次。
- `status`：投递状态。
- `submitted_at`：投递时间。
- `failure_reason`：失败原因。
- `platform_message`：平台返回提示。
- `duplicate_detected`：重复投递标记。

投递状态限定为：

- `pending_review`
- `approved`
- `submitted`
- `failed`
- `skipped`
- `duplicate`

## 运行时状态流

1. 用户导入简历，系统生成 `resume_profile`。
2. 求职模块读取 `resume_profile` 并生成求职画像。
3. 用户确认或调整筛选条件。
4. 采集编排器按平台创建采集任务并持续记录进度。
5. 平台适配器只读采集岗位并保存标准岗位对象。
6. 筛选服务应用硬过滤和排序偏好。
7. 评估层批量生成岗位评估报告。
8. GUI 展示候选岗位清单。
9. 用户批量勾选并确认投递。
10. 投递执行层在提交前重校验确认批次。
11. 平台投递适配器按确认批次执行投递。
12. 系统更新投递记录并展示批次结果。

## 安全边界

- 浏览器自动化只复用用户现有 Chrome 登录态。
- 平台账号、密码、cookie、token 不进入配置文件、日志、SQLite session state、LLM prompt。
- 投递前必须有用户批量确认。
- 投递执行前必须重校验确认批次，覆盖岗位下线、JD 变化、已投递、按钮失效。
- 清空求职数据只删除岗位、评估和投递记录，不删除简历原文件，不影响 Chrome 登录态。
- LLM 输入只允许包含简历画像、JD 文本和岗位结构化字段。
- 错误展示不得输出敏感凭据、账号标识或浏览器会话内容。

## GUI 设计

新增求职投递模块，包含以下视图：

- 求职画像确认页：展示简历推导结果和可编辑筛选条件。
- 岗位采集进度页：展示平台进度、采集数量、失败平台和可重试入口。
- 岗位清单页：展示匹配分、硬条件状态、公司、岗位、薪资、城市、风险。
- 岗位详情页：展示 JD 摘要、匹配优势、风险、缺失信息、简历建议、投递话术。
- 批量确认弹窗：展示选中岗位数量、平台分布、风险提示和确认按钮。
- 投递结果页：按批次展示成功、失败、跳过、重复拦截。
- 数据清理入口：清空本地求职数据。

## 错误处理

- 登录失效：停止对应平台任务，提示用户在 Chrome 中恢复登录。
- 验证码或账号风控：暂停对应平台任务，进入人工接管状态，用户处理后才能继续。
- 频率限制：记录限流原因，按平台退避策略暂停，不继续高频请求。
- 强制弹窗：暂停当前平台任务，提示用户人工处理后恢复。
- 页面结构变化：记录平台、页面 URL、失败阶段和解析错误类型。
- 字段缺失：标记低置信度，不直接排除。
- 投递按钮不可用：记录 `skipped` 或 `failed`，保留平台提示。
- 重复岗位：记录 `duplicate`，不进入投递队列。
- 确认批次陈旧：投递前发现岗位下线、JD 变化、已投递或按钮失效时，写入可观测结果并跳过对应岗位。
- 部分投递失败：保留成功结果，失败项允许重试。
- 节点失败：写入失败状态，不污染成功结果。

## 验收标准

- 能从 `resume_profile` 生成可编辑求职画像。
- 能从 BOSS 直聘、拉勾、猎聘采集标准岗位对象。
- 能观测平台级采集进度、失败原因、重试状态和人工接管状态。
- 能按全条件筛选岗位，并区分硬过滤、排序偏好和低置信度字段。
- 能为岗位生成匹配分、风险、改进建议和投递话术。
- 能展示批量审核清单，并在用户确认后执行投递。
- 能在投递前重校验确认批次，避免提交已下线、已变化或已投递岗位。
- 能记录每个岗位的投递状态和失败原因。
- 能清空本地求职数据且不影响简历原文件和 Chrome 登录态。
- 日志、LLM prompt、session state 不包含账号凭据、cookie、token。
